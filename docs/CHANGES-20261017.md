### RA1 目录 fsync（.NET / Kotlin / Dart）

| 语言 | 结论 | 实现 |
| :--- | :--- | :--- |
| .NET | **全托管路径实测不可用** | `File.OpenHandle(dir)` 在 Linux 上抛 `UnauthorizedAccessException`（.NET 8.0.426 实测），`RandomAccess.FlushToDisk` 无法用于目录；保留尝试并在首次失败后置位 `_dirSyncUnavailable` 不再重试，`onWarning("onDirSyncUnavailable")` 上报一次；Windows 直接跳过；netstandard2.0/Unity 为 no-op；**未引入 P/Invoke** |
| Kotlin | Linux 可用，macOS 可能 EINVAL | `FileRotation.fsyncDirectory`：`FileChannel.open(dir, READ).force(true)`，try/catch 返回布尔；调用方 `fsyncParentDirBestEffort` 失败只告警一次，不让轮转失败 |
| Dart | 无目录 fd API，无可行实现 | 明确 no-op + 代码注释与文档说明（不为该窗口引入 FFI） |

已用 WSL(Ubuntu, .NET 8.0.426) 端到端验证：Linux 上写入成功、`onDirSyncUnavailable` 只上报一次、进程无异常。

### RA2 自适应压实（五语言）

- **新增死键比例触发器**：`fileSize >= 2 MB` 且死数据占比 `>= 50%` 时压实，与原有 `compactionThresholdBytes` 触发器并列；`threshold == 0` 仍关闭全部自动压实。
- **O(1) 增量账本**：`livePayloadBytes = Σ(len(key)+len(value))`。Rust 在 `DbInner::mem_put/mem_delete/mem_drop/mem_clear` 统一收口（同时把 8 处分散的内存变更闭包收敛到这四个方法，并让 `apply_entries` 装载路径同样记账）；Go/Kotlin/Dart/.NET 在 `NamespaceStore.put/delete` 内记账，`.NET` 的批量快速装载路径额外调用 `RecalculateLiveBytes()`。
- 复用现有 `maybeCompactAfterWrite` 的退避/失败计数体系（D2 契约不变，不新增公开选项）。

**测试**：新增 15 个用例（每语言 3 个：比例触发、2 MB 基线、零阈值总开关）。Dart 51、Go 全通过、Kotlin 55、.NET 96、Rust 全通过。

## 10:22:42 — 批次 1：默认值可靠性优先与 Dart 默认值对齐（RA3 / RA4）

**背景**：2026-10-16 的缺口评审确认 Dart 三处默认值（`lockTimeoutMs` 5000、`syncIntervalMs` 50、`compactionThresholdBytes` 0）落后于其余四语言（C8/C19 欠账）。其中 `compactionThresholdBytes = 0` 会**关闭 Dart 的 WAL 自动压实**，属行为级漂移而非数值差异。

**决策**：默认值以"可靠性优先、简单可靠"为准——维持 `SnapshotAtomic` + `Immediate`，不因吞吐指标调整默认值；高吞吐场景由调用方显式选择 `AppendOnlyLog`。
