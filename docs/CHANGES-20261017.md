### FIX-21 AOL 压实阈值悬崖（Rust + .NET + 规范）

- **根因**：`maybe_compact_after_write` 以"文件绝对大小 ≥ 阈值"触发，而压实后文件恰等于存活大小 → 存活数据 ≥4MB 后每次写都全库重写。实测 6MB 存活 26.1ms/写（38 ops/s）、20MB 86.0ms/写（12 ops/s），对照（关闭压实）0.2ms。
- **修法**：改为 `garbage >= max(threshold, live/4)`，`garbage = fileSize − live`。**不引入**原计划的 `bytes_appended_since_compaction` 计数器：派生式无需新增状态、重开库后依然正确（计数器会清零），且 `live_payload_bytes` 本就是 O(1) 账本。
- 文件：`src/rust/src/db.rs`（`maybe_compact_after_write`）、`src/dotnet/src/Ckv/Db.cs`（`MaybeCompactAfterWrite`）、`docs/KV-DB-DESIGN-SPEC.md` §4.5。
- 测试：`src/rust/tests/wal_threshold_cliff_test.rs`、`src/dotnet/tests/Ckv.Tests/WalThresholdCliffTest.cs`（行为断言，无时间阈值）。红验证：移除修复后两个断言均失败，且耗时从 2.4s 膨胀到 113s。

### FIX-01 后台刷盘竞态（Rust + .NET）

- **根因**：`bg_flush_step` 在锁外写共享 `<db>.tmp`，与显式 `flush()` 并发；且轮转前不校验代际，陈旧快照可覆盖已确认写入并误清 `is_dirty`。
- **修法**：`DbInner` 增加 `flush_mutex: Arc<Mutex<()>>` 与 `dirty_generation: u64`（.NET：`SemaphoreSlim(1,1)` + `_dirtyGeneration`）。所有 `.tmp` 生产者互斥；bg 轮转前校验代际，不一致则删除 `.tmp` 并保留脏标记。锁序恒为 `flush_mutex → RwLock`；AOL 路径不取 flush_mutex（只 fsync），避免循环等待。
- 文件：`src/rust/src/db.rs`（`bg_flush_step` / `flush` / `close` / `compact` / `apply_mutation`）、`src/dotnet/src/Ckv/Db.cs`（`FlushIfDirty` / `Flush` / `Compact` / `Dispose` / `ApplyMutation`）。
- 测试：`src/rust/tests/deferred_flush_race_test.rs`、`src/dotnet/tests/Ckv.Tests/DeferredFlushRaceTest.cs`。
- **实证**：仅移除代际校验（保留互斥）时测试仍失败 → 证明"只加互斥不够"，两道保护都是必需的。

### FIX-02 跨进程锁语义（Rust，仅 a/c；.NET 共享模式不动）

- **修法**：(a) `FileLock::acquire` 把 `open(<db>.lock)` 纳入退避循环，Windows `{5,32,33}` 与 `WouldBlock` 视为竞争，超时后返回 `DbError::Locked`（此前 .NET 持 `FileShare.None` 时 Rust 立即 `IoError`，`lock_timeout_ms` 被绕过）；(c) `close()` 显式释放内核锁，并置 `closed=true`、从同进程注册表移除。
- **保留 `FileShare.None`**：规范 §1.1 明确不支持多进程并发读写，锁的职责是快速失败；放开共享会把 .NET 的强制互斥降级为 advisory。
- 文件：`src/rust/src/lock.rs`、`src/rust/src/db.rs`（`close`、`check_writable`、`closed` 字段）。
- 测试：`src/rust/tests/lock_close_release_test.rs`（close 后外部可加锁、重开 <500ms、Windows 共享冲突→`Locked` 且耗时≥150ms）。
