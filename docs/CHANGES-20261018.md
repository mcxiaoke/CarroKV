## 2026-10-18 15:02:14 — 修复批次 B：AOL 持久性守卫、部分写回缩、Kotlin MANUAL 语义与 Go/.NET 并发缺陷

1. **AOL 后台刷盘缺代际守卫（N-X2，Rust/Go/Kotlin 三语言）**：
   - 原实现 fsync 之后无条件清 `is_dirty`，且计划阶段从不采样代际（Rust 占位 0、Go 根本没采样、Kotlin `generation` 变量在 AOL 分支未赋值）。在 fsync 与清标记之间追加的帧从此再无 fsync 机会，`close()` 也会因标记已清而跳过——掉电丢失"已确认成功"的写；
   - 三语言统一为：计划阶段采样 `dirty_generation` → fsync 成功后才取写锁比对 → 一致才清脏，且 fsync 失败/文件打不开一律保持脏标记；
   - Rust 抽出 `aol_flush_should_clear_dirty()`、Go 抽出 `aolFlushMayClearDirty()`，各补 3 条/1 条单元测试覆盖"代际已变/一致/已关闭"三种情形。
2. **AOL 部分写失败不回缩（M2-03，Rust/Go/Dart/Kotlin 四语言）**：
   - 任一帧写失败时，撕裂的尾帧留在日志里，此后 `precheck` 会把"自己写坏的文件"误判成外部并发修改，同一条连接再也写不进去（直到重开并截断尾部）。Rust 原实现连 `finally` 都没有、Kotlin 是空 `finally {}`；
   - 四语言统一记录追加前偏移，写失败 `truncate/set_len` 回缩后再抛错；Rust/Go 另把"fsync 失败"与"写失败"区分开（前者保留字节、标记脏、推进磁盘账本，避免账本失真）。
3. **Kotlin `SyncMode.MANUAL` 语义反向（N-X3）**：分流条件 `== DEFERRED` 改为 `!= IMMEDIATE`。旧实现把 MANUAL 折进两阶段提交，每次 put 都全量序列化 + fsync，API-SPEC §3.1 的 "Manual：内存只写" 完全失效。新增用例断言"首写与第五十写的文件长度相同、300ms 空闲后仍不变、flush 后才落盘"（回退条件后该用例失败）。
