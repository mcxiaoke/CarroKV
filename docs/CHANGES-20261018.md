### 1. 前台 Immediate 路径两阶段提交（项 28 / P1-29）
- **核心优化**：彻底重构 5 门语言（.NET, Go, Dart, Kotlin, Rust）在 Snapshot 引擎 Immediate 模式下的写路径：
  - **阶段一（短写锁）**：磁盘预检、执行内存变异、提取只读快照副本（CoW 浅拷贝字典/切片引用，纳秒~微秒级），立即释放读写锁；
  - **阶段二（锁外序列化与落盘）**：在无读写锁保护（仅持有 `flushGate` / `flushMutex` 串行写临时文件）下执行快照序列化落盘与 `fsync`，并发读完全零阻塞；
  - **阶段三（短写锁轮转）**：毫秒级原子重命名文件并更新磁盘账本；
  - **阶段四（锁外派发）**：锁外统一触发 Watchers 与 Warnings 回调。

### 2. CoW 克隆粒度细化（项 29 / P1-1）
- **杜绝 O(N²) 重复克隆**：
  - 在同一事务/Batch 内引入 `clonedInTx` 集合跟踪，同一命名空间至多克隆一次；
  - 后续同命名空间的写/删操作直接在已克隆的副本上原地就地修改，彻底消除大批量批处理时的 GC 压力与内存尖峰。

### 3. `onWarning` 移出写锁（项 30 / P1-33）
- **排队与锁外统一派发**：
  - 5 门语言统一引入 `pendingWarnings` 内部队列；
  - 持有写锁期间（如自动压实失败、目录 fsync 不支持等）只入队告警信息；
  - 在完全释放读写锁之后统一向用户配置的 `onWarning` 回调派发，彻底消除因在告警回调中重入读库导致的死锁隐患。

### 4. 提交失败后的脏标记保留与内存原子回滚（项 31 / P0-7、P1-6）
- **内存原子回滚机制**：
  - 写操作前记录受影响命名空间的原始快照指针；
  - 一旦序列化、落盘 `fsync` 或轮转发生 IO 异常，立即原子回滚内存到写操作前状态；
  - 保留 `isDirty = true`，使后续显式 `flush()` 或后台刷盘仍能重试，绝不静默丢失数据；
  - 包装并抛出标准 `IoError`（.NET: `IoException`, Go: `ErrIO`, Dart: `IoError`, Kotlin: `IoError`, Rust: `DbError::Io`）；
  - 彻底消除了因失败未回滚导致重试时的 double increment（累加操作误多加一次）严重漏洞。

### 5. 一等公民异步接口补齐（项 32）
- **5 语言异步 API 对齐**：
  - **.NET**: `Task FlushAsync()`, `Task BackupAsync(string dest)`
  - **Go**: `FlushAsync() <-chan error`, `BackupAsync(dest string) <-chan error`
  - **Dart**: `Future<void> flushAsync()`, `Future<void> backupAsync(String dest)`
  - **Kotlin**: `CompletableFuture<Void> flushAsync()`, `CompletableFuture<Void> backupAsync(String dest)`
  - **Rust**: `JoinHandle<Result<()>> flush_async()`, `JoinHandle<Result<()>> backup_async(P)`
- **`backup` 优化**：读锁内只提取快照数据，序列化落盘与 fsync 全部移至锁外，写者零阻塞。

### 6. CRC32 硬件加速评估（项 33）
- **Go 语言**：替换为标准库原生自带的 `hash/crc32.ChecksumIEEE`（Go runtime 在 amd64 与 arm64 架构下自动调用 CPU 原生 SSE4.2 / ARMv8 CRC32 硬件指令），零外部依赖，实测吞吐提升数倍；
- **Rust 语言**：手写 256 表查表法在小配置/状态文件（KB 级）下耗时仅微秒级，经评估决定保留纯标准库零依赖设计，避免引入额外第三方 crate，保持 pure-native 极简特性。

### 1. Kotlin 语义反向修复与接口补齐（条目 23、24、20、19）
