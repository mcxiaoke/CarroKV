### 1. Kotlin 语义反向修复与接口补齐（条目 23、24、20、19）
- **修复 `clearNamespace` / `clear` 语义反向（§7.6，高危）**：
  - 彻底废除旧实现中 `clear(ns)` 直接调用 `dropNamespace(ns)` 导致物理移除命名空间的严重缺陷；
  - 正确实现 `clearNamespace(ns)`：保留命名空间元数据（`namespaces()` 依然能列出），仅清空内部所有键值对；
  - 写入 WAL 时追加 `OP_DELETE` 墓碑或重写快照，并向监听器派发单个 `KeyChangeOp.CLEAR` 事件（Key 为空串），返回 `Boolean`（此前是否有条目被清空）；
  - `clear(ns)` 作为兼容别名重定向至 `clearNamespace(ns)`。
- **修复 `dropNamespace` 返回值与事件派发（§5.2.2、条目 24）**：
  - 返回值由 `Unit` 改为 `Boolean`（表示该命名空间此前是否存在并被 drop）；
  - 存在时仅派发单个 `KeyChangeOp.DROP_NAMESPACE` 事件（Key 为空串），杜绝旧实现逐键派发误导性 DELETE 事件。
- **扩展 `KeyChangeOp` 为 4 值标准 ABI（条目 24）**：
  - `Types.kt` 扩展为 `PUT`, `DELETE`, `DROP_NAMESPACE`, `CLEAR` 4 值枚举。
- **`BatchWriter` 补齐 `clearNamespace`**：
  - 支持批处理内清空命名空间，并在批次提交前自动清理本批次先前针对同一命名空间的 `OP_PUT`，避免已清空键复活。
- **补齐 `iterPrefix` 前缀扫描（条目 20）**：
  - `CkvDb` 门面与 `Snapshot` 同步补齐 `iterPrefix(ns, prefix)` 方法，收集匹配前缀条目并安全跳过损坏的 UTF-8 键。
- **补齐 `isClosed` 属性（条目 20）**：
  - 暴露 `val isClosed: Boolean get() = isDisposed`。
- **`putBytes` 入口防御性拷贝（条目 19 / P1-30）**：
  - `CkvDb.putBytes` 与 `BatchWriter.putBytes` 执行 `value.clone()` 防御性拷贝，防止外部数组篡改污染内部状态。
- **测试验证**：新增 `BatchThreeContractTest.kt`（6 个测试全绿），`./gradlew test` 全量 78 个测试 100% 全部通过。
