# Project Changes 2026-10-15

## 2026-10-15 15:10:54

- **docs/KV-DB-DESIGN-SPEC.md**: 规范从 v3.0 升级至 v3.1 实施定稿版，完成 6 大工程实施死角的闭环锁定：
  1. **空库生命周期闭环**：确立 32 字节文件头为合法空库形态（$N=0$），消除 `1 <= OpCount` 规约冲突，定义初始 `TxID = 0`。
  2. **两代原子轮转替换协议（Atomic Rotation）**：弃用先写 `.tmp` 再复制 `.bak.tmp` 的方式，采用覆盖重命名轮转旧文件，消除 200% 写放大与磁盘满（ENOSPC）崩溃死锁风险。
  3. **类型系统与多态读写契约**：明确 `ValueType`（`Bytes` vs `Utf8String`）在 `getString`/`getBytes` 交叉读取时的解码策略与强类型异常行为；固化 `Entry` 结构体规范。
  4. **内存模型与无符号 UTF-8 排序器规范**：明确必须基于 0..255 无符号字节序对比，解决 C# `SortedDictionary` 默认 UTF-16 比较器与 Emoji 排序断层；固化 `scanRange` 的边界与空值语义。
  5. **实例级线程安全性（Thread-Safety）**：明确规范所有语言的 DB 实例均为进程内多线程并发安全，内部基于读写锁管理并发。
  6. **Windows 锁窃取与轻量 TxID 定位**：吸收实机实测结果，规范在 Windows 上遭遇 `WinError 32/33` 时判定持锁者依然存活并禁止窃取的逻辑；规定快照模式下写锁检查通过只读 28B 帧头的轻量跳跃扫描定位最新 `TxID`。
  7. **测试向量附录实机核算**：补充经过真实数学与算法核算的 32B 空库标准镜像、80B 单条 Put 快照镜像的精确 Hex Dump、CRC32 与 SHA-256。
